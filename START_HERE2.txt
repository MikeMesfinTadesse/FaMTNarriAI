 SECTION C: ON-PREMISES DEVOPS LEARNING PATH (REAL COMPANY)
####################################################################
(No AWS, No Terraform, No Public Cloud. Only Local Servers + Docker)

-----------------------------------------
🏗️ LESSON 1: ANSIBLE (CONFIGURING LOCAL SERVERS)
-----------------------------------------
Ansible is how companies install Docker and set up servers without 
clicking buttons. It uses SSH to configure 1 or 100 servers at once.

1. Open Ubuntu terminal (PowerShell -> wsl).
2. Install Ansible:
   sudo apt update
   sudo apt install ansible -y
3. Check version:
   ansible --version
4. Create a test inventory file (list of servers):
   nano inventory.ini
   (Type: localhost ansible_connection=local)
5. Create your first playbook (e.g., install_nginx.yml):
   nano install_nginx.yml
   (Write YAML steps to install Nginx)
6. Run the playbook:
   ansible-playbook -i inventory.ini install_nginx.yml

-----------------------------------------
🏢 LESSON 2: GITLAB CI/CD + DOCKER (ON-PREMISES)
-----------------------------------------
Colleague's Company Setup: They use GitLab CI/CD to build Docker 
images and deploy them to their own physical servers via SSH.

Key Concepts to Learn:
1. GitLab Runner: The agent that runs the deployment jobs.
2. .gitlab-ci.yml: The file that defines the pipeline (build, test, deploy).
3. Docker on the Server: How GitLab uses SSH to run "docker compose up -d".
4. GitLab Container Registry: Storing images securely inside GitLab.

-----------------------------------------
📊 LESSON 3: MONITORING (PROMETHEUS & GRAFANA)
-----------------------------------------
Even on-prem servers need monitoring. 
Prometheus collects metrics (CPU, memory) and Grafana displays them.
(You can practice this on your local Minikube cluster!)

1. Enable monitoring in Minikube:
   minikube addons enable metrics-server
2. Install Prometheus/Grafana via Helm:
   helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
   helm repo update
   helm install monitoring prometheus-community/kube-prometheus-stack
3. Open Grafana:
   minikube service monitoring-grafana


====================================================================
🛑 THE GOLDEN RULE FOR SHUTDOWN
====================================================================
Before you turn off your PC, ALWAYS run "minikube stop" in 
whatever terminal you were using (Git Bash, Ubuntu, or PowerShell). 
This prevents the corrupted SSH errors we fixed earlier!

If Minikube breaks: 
Run "minikube delete" and then "minikube start" again.
